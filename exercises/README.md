# Week 1 → Week 2: інтерактивні таски

Це перевірка не коду, а **розуміння коду, який ти вже написала**. Нічого нового вчити не треба — усе спирається на твій `index.js`.

## Як запустити

```bash
npm install                # один раз, якщо ще не робила
node exercises/run.js      # і все
```

Далі програма веде тебе сама: показує один таск за раз, пише, що конкретно зробити, чекає — і перевіряє, коли ти будеш готова.

Сервер окремо запускати **не треба**: перевірка сама його піднімає, робить запити і зупиняє.

### Що можна натискати

| Клавіша | Що робить |
|---|---|
| `Enter` | перевірити поточний таск |
| `s` | пропустити цей таск і піти далі |
| `q` | вийти (нічого не загубиться, продовжиш потім) |

Вийшла — заходиш назад тією ж командою: програма сама подивиться, що вже зроблено, і продовжить з потрібного місця.

Інші варіанти запуску, якщо знадобляться:

```bash
node exercises/run.js 04     # почати одразу з таска 04
node exercises/run.js --all  # просто прогнати всі перевірки без діалогу
```

## Одна зміна, яку вже зробили за тебе

У `index.js` рядок `const PORT = 3000;` став таким:

```js
const PORT = process.env.PORT || 3000;
```

Навіщо: перевірка щоразу піднімає твій сервер на вільному порті, щоб не сваритися з тим, що вже могло зайняти 3000. `process.env.PORT` — це змінна оточення, тобто значення, яке передають програмі ззовні, не змінюючи код. `|| 3000` означає «а якщо нічого не передали — працюй на 3000, як і раніше». Твій звичайний `npm start` від цього не змінився.

Це не хитрість заради тестів: так влаштовані всі справжні застосунки. Порт, адреса бази, ключі до сервісів приходять ззовні — бо на твоєму ноуті й на сервері вони різні.

## Три типи тасків

**ПЕРЕДБАЧЕННЯ** (01 і 03). Ти відкриваєш файл у `exercises/answers/`, пишеш, що **на твою думку** станеться, і лише потім запускаєш перевірку. Вона покаже поруч дві речі: що думала ти і що сталося насправді.

> Тут одне правило, і воно важливіше за результат: **спершу відповідь, потім запуск**. Якщо підглянути — таск перетворюється на переписування чисел і не дасть нічого. Помилитись не соромно, у цьому весь сенс: ти побачиш, де твоя картинка коду розійшлася з реальністю.

**КОД** (02, 04, 05, 06, 07). Перевірка червона, поки ти не допишеш або не полагодиш щось у `index.js`. Що саме — програма скаже перед таском, а повний опис лежить угорі відповідного файлу в `exercises/tasks/`.

**ДЕМО** (08). Нічого писати не треба, просто дивишся.

## Порядок і приблизний час

Іди по порядку, не перестрибуй — кожен наступний спирається на попередній.

| # | Про що | Що робиш | ~час |
|---|---|---|---|
| 01 | HTTP-методи та статус-коди | заповнюєш `answers/01-http.answers.js` | 20 хв |
| 02 | params / query / body | додаєш `POST /debug/echo/:id` | 20 хв |
| 03 | читання коду без запуску | заповнюєш `answers/03-code-reading.answers.js` | 15 хв |
| 04 | баг: id, що повторюється | лагодиш генерацію id у users і todos | 20 хв |
| 05 | баг: тип поля `completed` | додаєш перевірку типу в `/todos` | 25 хв |
| 06 | новий ресурс `/products` | пишеш повний CRUD з нуля | 60–90 хв |
| 07 | фільтрація через query | доробляєш `GET /products` | 25 хв |
| 08 | дані живуть у пам'яті | просто дивишся | 5 хв |

Коли таск зеленіє, програма друкує **«ЧОМУ САМЕ ТАК»** — прочитай, це і є та частина, заради якої все робилось.

## Правила

1. **Не редагуй файли в `exercises/tasks/` і `exercises/lib/`.** Перевірка має лишитись чесною. Твоє місце — `index.js` і `exercises/answers/`.
2. **Читай жовті підказки під червоними рядками** — там не просто «не так», а чому саме.
3. **Застрягла більше ніж на 30 хвилин — пиши, не сиди.** Застрягти нормально, мовчки згоріти — ні.
4. Роби коміт після кожного зеленого таска — програма сама нагадає командою.
5. Файли з `answers/` теж комітимо: по них ми пройдемось разом.
